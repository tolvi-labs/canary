## Session — Reframed Canary from Compliance Canary to vault-informed CI test selection

**Tickets:** none

### What happened
- From a Tolvi Labs positioning pass (personal brand vault), reframed Canary. The 07-04 decision had benched **Compliance Canary** as an ecosystem orphan and gated any revival on it compounding with the vault. The resolution isn't to rescue the compliance tool — it's to **reclaim the name** for a different product: **vault-informed CI test selection** that consumes Provenance's impact output and is ranked by the vault, so it compounds by construction.
- Locked the identity and boundaries: **Provenance reasons (code → risk); Canary gates (code → tests → gate).** Canary consumes Provenance's impacted-code output and turns it into an executable CI artifact + gate — a job no other tool owns (the boundary discipline that killed Guild). vs Forge: Forge drafts tests, Canary maps and gates them; Canary's audit is Forge's to-do list.
- Nailed the mechanism: coverage-instrumented test↔code map (base) + vault-declared bindings (the "never auto-skip these" overrides, e.g. stale-cache incident → always run these integration tests). The vault bindings are the moat vs a me-too Launchable.
- Resolved the manifest model: `globalManifest` (durable full registry + coverage map, the only thing that can drift, refreshed at commit-time) vs `localManifest` (per-PR subset, derived fresh, cannot drift, never accumulates). This collapsed the "too many manifests / bloat" worry into a single freshness job on the global map.
- Set the gate policy (chose the safety-maximal option): PR → localManifest; **merge to main → globalManifest (full)**; release tag → globalManifest. Grounded in "per-PR passes don't compose into a release guarantee" — enforce the best practice, keep the engineer conscious, never silently automate the skip.
- Scoped v1 as (A) CI test-selection, with (B) "cheap early-warning guard at every gate → prod-watch sentry" as the stated north star, retiring the suite reframe's third-Canary placeholder.
