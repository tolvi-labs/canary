# Canary ships as a Go CLI implementing vault-informed CI test selection, using per-test isolated coverage instrumentation and a two-manifest model

**Date:** 2026-09-09
**Repo:** canary

## Why

The 2026-07-08 reframe committed Canary's identity (vault-informed CI test selection) and the 2026-07-22 refinement settled its boundary with Provenance, but neither decided the implementation form or how the coverage map would actually be built — both were explicitly left open in `docs/test-selection-kickoff-prompt.md`. Like Provenance, Canary has to run with no LLM in the loop (a CI required check, a commit-time refresh, an optional local git hook), which rules out the Claude Code skill form factor entirely and makes it a standalone binary by necessity, not preference.

## How

- **Form: a standalone Go binary (`canary`)**, mirroring Provenance's own `2026-09-08-provenance-ships-as-go-cli` decision and matching the sibling `tolvi`/`forge`/`provenance` command style. Module path `github.com/tolvi-labs/canary`.
- **The coverage map (the moat, part 1): per-test isolated coverage**, not aggregate single-run or static/import-graph mapping (the latter was already explicitly rejected for v1 by the 2026-07-08 decision as "too coarse to trust a skip on"). For each package: compile its test binary once (`go test -c -cover`), then invoke it once per test with `-test.run '^TestX$' -test.gocoverdir=<dir>` (Go 1.20+'s binary coverage format — the flag, not the `GOCOVERDIR` env var, actually writes coverage data), convert with `go tool covdata textfmt`, and parse with `golang.org/x/tools/cover.ParseProfiles`. The expensive per-test cost is paid only at `canary init`/`canary refresh` time; `canary check` at PR time is a pure lookup against the already-built map, no test execution.
- **The vault bindings (the moat, part 2): a new `x-canary-bindings` decision field**, under the same `x-*` extension namespace Provenance's `x-governs` already uses (no change to the shared `tolvi` repo's schema required). A binding maps path globs to test names; only `status: active` decisions participate. A binding naming a nonexistent test fails open — reported as a warning, never a hard block — matching Provenance's well-formedness-only validation philosophy. See `docs/vault-bindings.md` for the end-user-facing schema reference.
- **Two manifests.** `globalManifest` (`.canary/global-manifest.json`) is the full test registry + coverage map, the only artifact that can drift; a staleness check (is `BuiltAtSHA` an ancestor of HEAD?) falls back to the full suite rather than trusting a stale map. `localManifest` is derived fresh every `canary check` from `diff + globalManifest + vault bindings`, never persisted.
- **Three-tier gate policy.** PR → coverage-derived local selection. Merge to main / release tag → always the full suite from `globalManifest`, ignoring the diff entirely — per-PR passes don't compose into a release guarantee (PRs interact; a local selection was computed against a base that has since moved).
- **Safe-failure defaults, all in the conservative direction — never a silent skip:**
  - A package that fails to compile for coverage is recorded in `DegradedPackages`/`BuildWarnings` rather than aborting the whole build; a diff touching it force-includes everything known about that package (tagged `degraded-package-fallback`).
  - A changed `.go` file with **no** entry in the coverage map at all — a brand-new file, or a degraded package with zero coverage history — falls back to the full suite (`ManifestStatus: "partial-fallback"`, tagged `unmapped-code-fallback`). This case was found missing during a whole-branch review after the rest of v1 shipped, reproduced empirically (a new file + its own new test scored `selected_tests: []` while reporting `"fresh"`), and closed in two passes: the first pass's fix accidentally excluded degraded packages with zero coverage history from the new check (since their existing fallback mechanism has nothing to force-include for them), reproducing the original bug in a narrower form; the second pass gated the exclusion on the degraded package actually having coverage history to offer.
  - A missing/stale manifest falls back to the full suite with a loud warning — never a block, since running everything is the conservative direction, not a risky skip.
- **Audit mode is part of v1**, not deferred: `canary init --audit` / `canary audit` report orphan tests (never executed by anything) and untested paths (zero covering tests anywhere) — Forge's to-do list, never auto-generated by Canary. **Known limitation, found by dogfooding against the real `provenance` repo:** coverage-based orphan/gap detection cannot see across a subprocess-exec test boundary (`exec.Command("go", "run", ...)`-style CLI tests, an idiomatic pattern for testing a `main()` entrypoint end-to-end). This produced false-positive "orphan"/"untested" reports for `provenance`'s own `cmd/provenance/main_test.go` and 100% of its `main.go` body, despite both being genuinely exercised. Not a bug in the coverage-mapping logic (it correctly reports what `go test -cover` measured); a real, recurring gap on any target repo using that test style, deferred to a follow-up rather than patched into v1.
- **The git hook is Canary's own `.git/hooks/post-commit` shim** (`canary hook install`), calling `canary refresh` — not a `tolvi-commit` plugin (verified directly: the `tolvi` CLI has no plugin/modifier extension point for third-party tools). Originally specified as `pre-commit`; corrected to `post-commit` during final review, since at pre-commit time `HEAD` still points to the previous commit, which would make every refresh target the wrong range and leave the manifest permanently one commit behind.
- **CI integration is a documented pattern** (`docs/ci-integration.md`), not a published GitHub Action, matching Provenance's own platform-agnostic positioning.
- **v1 is Go-only, no config file** — no `canary.yml` equivalent to Provenance's `provenance.yml`; bindings live directly on decision frontmatter and repo-level settings weren't needed for anything built.

## Outcome

Canary moved from pre-build to a working v1: `cmd/canary` (`init`, `audit`, `check`, `refresh`, `hook install/uninstall`), the per-test coverage engine, the `x-canary-bindings` convention, the two-manifest model, the three-tier gate with all its safe-failure paths, audit mode, and documented CI integration — all covered by real, executable tests (temp git repos and real Go fixture modules, no mocks), independently re-verified across three rounds of review (per-task, whole-branch, and a scoped re-review of the whole-branch fix wave). Dogfooded against the real `provenance` repo: a genuine two-file commit correctly narrowed 35 tests down to the 5 that actually covered the change, with correct impact attribution. Building Provenance's own docs/PLAN.md "scope (B)" prod-watch sentry, and tuning the `x-canary-bindings` glob calibration against a real dogfooding cadence, are the natural next steps.

> Superseded by [[2026-09-11-canary-multi-language-coverage]] — the "v1 is Go-only, no config file" claim no longer holds; Canary added Python and Node coverage backends and a `canary.yml` config file.
